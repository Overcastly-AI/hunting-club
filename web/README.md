# Web admin page (`@huntclub/web`)

The club admin page at `huntclub-dev.jaycobjones.com`: Vite + React + TypeScript, served from S3 + CloudFront by `infra`'s Web stack (it deploys `web/dist`).

```sh
npm run dev -w @huntclub/web      # local dev server
npm run build -w @huntclub/web    # typecheck + build to web/dist (needed before `npm run synth`)
npm test -w @huntclub/web         # vitest + Testing Library (jsdom)
```

- **Design tokens** come from `@huntclub/design`, the same source as the app. `src/theme/css.ts` turns them into CSS variables and text classes. The Archivo font is bundled from the app's single copy (`app/assets/fonts/Archivo-Variable.ttf`).
- **Environment IDs** (region, Cognito pool, web client, club API URL) come from `CLOUD_ENVIRONMENTS` in `@huntclub/shared/cloud`, the same source the app and infra use (`src/cloud.ts`).
- **Sign-in:** email plus the emailed code through the shared `createCognitoAuth` and `ClubSession` (`@huntclub/shared`), with the same words as the app (`signInCopy`) and the same resend cooldown (`RESEND_CODE_COOLDOWN_SECONDS`, `@huntclub/shared/useCooldown`). The form floats over a captioned sample property (`src/map/sampleProperty.ts`).
- **Look:** the map-first design (docs/DESIGN.md). The shell (`src/shell`) is a rail on desktop and tablet and a top bar with a docked tab bar on phones; Sign out is only in the account menu. My club, sign-in, Stands and areas and Map packs draw the club plan (`src/map/ClubMap.tsx`): the club's own property line, areas and stands as SVG, in Web Mercator. My club and Map packs draw them over live USGS tiles from the shared `BASEMAPS` (`src/map/basemap.ts`), shown as plain images, so the CSP allows only that one host in `img-src` (`USGS_BASEMAP_ORIGIN`, never `connect-src`). My club's map pans and zooms anywhere (drag, wheel, arrow keys, its own buttons, Find me), with a Topo and Aerial switcher. Under the live tiles is the club's own ready map pack of the same basemap: the PMTiles archive is read by range from the admin's own origin (CloudFront serves `packs/`) and each tile shown as a `data:` image, so it still shows when the live tiles cannot load. With neither, the plan stands on a plain ground with a grid.
- **Property line:** club admins draw it on My club (`src/map/PropertyLineEditor.tsx`, state in `src/map/draw.ts`): click to add corners, drag or arrow-key a corner, Undo, Remove corner, Close shape, Save and Cancel. The shared rule (`propertyLineProblem` in `@huntclub/shared`) refuses a line that crosses itself, is too small or too big for a map pack, and the club API applies the same rule to `PATCH /clubs/:clubId` (`updateClub` in the shared client). The sign-in page draws the sample property over its own aerial pack, committed at `sample-pack/packs/sample/<id>.pmtiles` (about 200 KB; `scripts/sample-pack.ts` rebuilds it from USGS with the real map-pack builder) and deployed to the bucket by infra's Web stack, so no upload is needed. Page layouts are in `src/pages/styles.ts`.
- **Stands and areas:** club admins add a stand or an area from the Stands and areas section on My club. A stand is placed with a tap (or Put at the cross), dragged or moved with the arrow keys, named and typed (`STAND_TYPE_LABELS`) in `src/map/StandEditor.tsx`. An area is drawn with the same polygon tool (`DRAW_SUBJECTS.area`) and named in `src/map/AreaFields.tsx`. A saved stand opens for editing from its details (Edit stand), a saved area from its name on the map or its row in the list. Both delete after a confirm step (`src/map/DeleteConfirm.tsx`). Saves go through the shared client (`createStand`, `updateStand`, `deleteStand`, `createArea`, `updateArea`, `deleteArea`) to the club API's existing stand and area routes, checked first by the shared schemas: `StandCreateSchema`, and the area shape rule (`areaProblem`), which the API applies too.
- **Review build:** `npm run build:kit` also includes a demo of the admin over sample data (`/app/?demo=<scenario>`, `src/demo`), which production builds drop. `NODE_USE_ENV_PROXY=1 NODE_PATH=/opt/node-tools/node_modules node ../scripts/run-ts.mjs scripts/shoot.ts [folder] [shot,...]` (from `web/`) serves it with the real security headers and the sample aerial pack (committed in `sample-pack/`) at the demo club's key and, for every page at 1280 and 390 px in both themes, checks for CSP violations, sideways scroll, serious or critical axe issues and the dialog focus trap, and writes screenshots to `docs/redesign/<folder>/` (`m2` unless named).
- **Data:** every page reads a `ClubApi` (`src/api/types.ts`), implemented by `src/api/admin.ts` over the shared typed client (`createClubApiClient`, `API_PATHS`). Until the club API URL is in `CLOUD_ENVIRONMENTS`, the page says the club service is not available yet. Tests run the same adapter against an in-memory `ClubApiClient` (`src/__tests__/fakeClubApi.ts`).
- **Invites:** the link comes from `encodeJoinUrl` in `@huntclub/mesh`, and the QR from `qrMatrix` in `@huntclub/shared/qr`, drawn as SVG.
- **Routing:** the admin pages use hash routes (`#/roster`). The page also answers three real paths with no sign-in (`WEB_PAGE_PATHS` in `@huntclub/shared/app`, chosen in `src/Root.tsx`): `/join`, the fallback for https invite links (hands the invite to the app and shows its QR for a phone), and `/checkout/done` and `/checkout/cancel`, where Stripe Checkout returns. infra's Web stack serves `index.html` for every path without a file extension (a CloudFront Function, `infra/src/web-pages.ts`), so any other path shows Page not found; a missing file is a real 404.
- **Page head:** `site-head.ts` (a Vite plugin) writes the title, meta description and theme color into `index.html` and emits `favicon.svg` from the logo mark in `@huntclub/design`. Each screen sets its own tab title (`src/title.ts`). The Vite config imports workspace TypeScript, so every script runs Vite with `--configLoader runner`.
- **Harvests:** season summaries of the harvests members shared with the club (by species, sex, member and week) for a date range the admin picks, with CSV export. The counting rule is `harvestReport` in `@huntclub/shared`; days and weeks are the admin's local calendar days. If a reload fails for lack of a connection, the page keeps showing what was last loaded (`useAsync`'s `keepLastOn`).
- **Payment:** Billing starts Stripe Checkout through the club API (`startCheckout`) for an active plan whenever the club has no paid-up subscription; the page never holds Stripe keys.
